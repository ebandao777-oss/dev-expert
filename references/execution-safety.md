# 执行安全：审计、防线、清单、确认

本 reference 覆盖执行阶段的安全保障机制，收口于 Step 2（规划门禁）、Step 3（执行）。
引用以下机制（顺序对应执行流程）：

---

## 规划门禁（PLAN-GATE，Step 2 启用）

复杂任务在进入修改阶段前必须通过。Trivial Fix（单文件 ≤ 1 行，无结构变更）可跳过；虽通过但触发异常 → 强制中止。

```
☐ 1. 是否已遍历所有用户定制 / 人工干预文件？
☐ 2. 是否已覆盖所有相关依赖模块？
☐ 3. 外部系统 / 接口影响已评估？
☐ 4. 新引入库的许可证兼容性已确认？
☐ 5. 命令行 / 脚本参数完整无硬编码路径？
☐ 6. 数据库迁移回滚方案已就绪？
☐ 7. 测试集已选定或确认无需新测试？
☐ 8. 性能敏感路径已标注（需基准对比）？
☐ 9. 批量范围已确认（文件数 / 记录数 / 受影响 API 数）？
☐ 10. 回滚 / 恢复机制已定义？
☐ 11. 安全漏洞扫描已预判（SQL注入/XSS/路径遍历/信息泄露）？
☐ 12. 并发 / 竞态 / 幂等场景已考虑？
☐ 13. 方案已回读确认格式无乱码/截断？
☐ 14. 自动跳过项已注原因？
☐ 15. 中断点与恢复路径已标注？
```

---

## 写码前实码确认

修改或生成代码前，必须完成：

1. **读文件**：`read_file` 目标文件，确认上下文、编码、插入位置
2. **搜索关联**：`search_content` 在项目中搜关键函数名/类名/表名，确认无遗漏引用
3. **冲突检查**：确认当前文件无正在进行中的未合并变更

三项均完成后才允许进入修改操作。跳过任一项 → 退回 Step 2。

---

## 审计修复分离

适用于代码审查、Bug 诊断、重构建议等场景：

- **审计阶段**：只读操作，收集证据（问题清单、堆栈、日志、复现步骤），禁止修改任何文件
- **修复阶段**：审计阶段结束后，输出结构化诊断结论，经确认后才进入修改

两阶段不可交叉。审计未完成前改代码 → 视为未完成审计，退回重做。

审计输出格式（修复阶段的前置输入）：

```
## 审计结论
- 问题定位: {文件:行号}
- 根因分类: {框架行为/配置/缓存/竞态/逻辑错误/...}
- 影响范围: {受影响模块/功能}
- 修复方向: {最小改动方案}
- 验证方式: {如何确认修复有效}
```

## 不卡死计数器

同一诊断点在当前 session 内连续失败 ≥ 3 次 → 触发：

1. 暂停当前方向的修复尝试
2. 列出 2-3 条替代方案（不同策略，非参数微调）
3. 说明各方案的成本、风险与验证方式
4. 交用户选择后继续

禁止行为：同参数微调绕过计数器；换一句等价表述重试同一思路。

## 批量修改 7 防线

批量修改（同操作影响 ≥ 3 文件或 ≥ 10 处修改点）时启用：

| 防线 | 动作 | 失败处置 |
|---|---|---|
| 1. 预检 | 全局 `lint`（含 PHPStan/ESLint 等），确保基线干净 | FAIL → 修复后重跑 |
| 2. 试点 | 取 3-5 个代表性文件，试改 | 任意 FAIL → 调整规则后重试，上限 2 次 |
| 3. 备份 | 改前 `cp → .bak`，范围对齐批量计划 | 不可跳过 |
| 4. 批量执行 | 按计划逐文件执行 | 输出 `[OK/SKIP/ROLLBACK]` 逐文件日志 |
| 5. 后检 | 全局 `lint`，与前基线对比 | 新增问题 → 回退 |
| 6. MD5 校验 | 预期外变更文件输出 MD5 对比 | 标注差异来源 |
| 7. 回读确认 | 抽查 3-5 个文件，确认修改点正确 | 不一致 → 整批回退 |

回退规则：`ROLLBACK` 总量 > 20% → 整批回退。回退方式：倒序 `.bak` 恢复。

## 清单化质量自审

代码交付前逐条自审（收口于 SELF-AUDIT § 代码质量）：

```
☐ 异常处理完备（try-catch / 错误返回 / 边界条件）
☐ 硬编码常量已提取
☐ SQL / 外部输入已参数化
☐ 输出已转义（XSS / 模板引擎）
☐ 敏感信息不入日志/返回值
☐ 文件操作含路径白名单校验
☐ 超时/重试已设置上限
☐ 并发/竞态场景已处理
☐ 接口幂等性已保证（写操作）
☐ 注释与代码一致（无过期注释）
```

## 安全红线清单

文件操作、数据访问、用户输入处理等场景必须逐条对照：

```
☐ SQL 参数化（无字符串拼接用户输入）
☐ 输出转义（HTML / JS / URL 上下文）
☐ 文件路径白名单 / 拒绝 ../ 穿越
☐ 上传类型白名单 + 大小限制
☐ 敏感信息不入前端（密钥/Token/内部路径）
☐ CSRF Token（状态变更操作）
☐ 权限校验后端兜底（前端校验仅为 UX）
☐ 错误信息不泄露内部细节
☐ 第三方依赖版本已知漏洞已排查
☐ 日志不含密码/Token/身份证号
```
