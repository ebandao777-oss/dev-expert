## 触发与读取

### 诊断阶段触发

在 Bug 诊断 / 代码审查 / PHP 内联 JS 等 session 中，Agent 可使用正则或关键词匹配 `error_index.md` 行中的触发关键词。命中时：

- 读 `error_index.md` 同行的 ERR-ID
- 读 `errors/{ERR-ID}.md` 全文
- 若当前症状与记录匹配 → 优先复用修复方式，计时从 0 开始
- 若相似但不完全匹配 → 标记为变体，修复后新建 ERR-ID（不覆盖原条目）

### 新坑即录

任一 session 中踩的新坑且排查耗时超过 40 分钟（从初步定位到 fix 完成），强制性操作：

1. 分配下一个可用的 ERR-ID（如 ERR-004）
2. 按单条模板创建 `errors/{ERR-ID}.md`
3. 在索引表追加一行
4. 同步更新 `project_memory.md` 中的 Known Issues 节（写缩写引用：`参见 ERR-XXX`）

> **排查时间估算**：从首次发现症状到修复方案确认，按 Agent 与用户交互轮次×平均轮耗时估算；≥ 4 轮交互视为接近 40 分钟阈值，建议记录。

## 归档策略

- 索引表超过 50 行时触发归档提醒：`⚠️ 错误索引已超 50 条（当前 X 条），建议将 3 个月前的旧条目归档至 archive/error_index_{YYYY}.md`
- 单条 ERR-XXX.md 超过 500 行时触发拆分提醒
- 合并规则：连续 3 个 ERR-ID 同一根因 → 合并为一条，保留各变体修复方式
