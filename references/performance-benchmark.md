# 性能基准测试 -- 量化性能验证

## 输入要求

1. **目标代码路径**（必填）：被测函数/模块/脚本
2. **性能指标**（必填）：耗时 / 内存 / 吞吐量 / QPS / 启动时间，至少其一
3. **阈值**（可选）：目标上限，如"单次调用 < 200ms"；不提供则仅输出基准数据
4. **对比基线**（可选）：优化前的基准数据，用于 A/B 对比

## 执行流程

### 第一步：识别性能触发面

扫描代码，定位性能关键路径：
- 循环体内重计算（正则编译、字符串拼接、重复 I/O）
- 批量操作（大批次读文件、批量 SQL、批量网络请求）
- 数据结构选择（list vs set vs dict 查重、字符串拼接 vs join）
- 缓存缺失（重复调用同一开销大的函数 / 重复查询同一数据）
- 数据库查询（N+1、缺索引、全表扫描 — 发现后跳转 `mysql-database`）

### 第二步：选用测量工具

按语言和场景选择：

| 语言 | 工具 | 适用场景 |
|------|------|---------|
| Python | `cProfile` / `timeit` / `pytest-benchmark` | 函数级耗时、逐行热点 |
| Node.js | `console.time` / `benchmark.js` / `clinic` | 火焰图、事件循环延迟 |
| Go | `go test -bench` / `pprof` | CPU/内存 profile |
| Java | JMH | 微基准测试 |
| PHP | `microtime()` / Xdebug profiler | 函数耗时 |

**首选策略**：若项目已有测试框架，优先用其内置 benchmark（如 pytest-benchmark、go test -bench），降低接入成本。

### 第三步：执行测量并采集数据

- 跑 3 次取中位数，标注冷/热启动差异
- 记录环境：CPU 型号/核心数、内存、OS、Python 版本
- 内存测试记录峰值 RSS（`tracemalloc` / `memory_profiler` / `process.memory_info()`）
- 输出原始数据 + 整理后表格

### 第四步：生成瓶颈报告

对超出阈值的热点逐条分析：
- 热点代码位置（文件:行号）
- 当前耗时 / 内存占用
- 根因分析（为什么慢）
- 优化建议（具体方案 + 预期收益）

### 第五步：优化前后对比（如有基线）

| 指标 | 优化前 | 优化后 | 提升 |
|------|--------|--------|------|
| 耗时 | X ms | Y ms | Z% |
| 内存 | X MB | Y MB | Z% |
| 调用次数 | X | Y | Z% |

## 质量标准

- 必须跑 3 次以上取中位数，单次结果不可作为结论
- 必须标注测试环境（硬件 + 软件版本），否则数据不可复现
- 热点分析必须有具体代码位置（文件:行号），不得只说"某个循环慢"
- 优化建议必须给出可操作的方案，不得只说"优化一下"
- 不得在无基线对比的情况下声称"显著提升"

## 失败回退机制

| 步骤 | 失败条件 | 回退目标 | 最大重试 | 不可恢复时升级路径 |
|------|---------|---------|---------|------------------|
| 第一步：识别触发面 | 代码量过大无法定位关键路径 | 按函数分批，标注"仅部分路径" | 1 | 缩小范围到用户指定的入口函数 |
| 第二步：选用测量工具 | 工具不可用或安装失败 | 降级到语言内置 time 打点 | 1 | 输出手动计时方案，标注精度受限 |
| 第三步：执行测量 | 环境差异导致数据波动 > 20% | 增加采样次数到 7 次，输出方差 | 2 | 标注"环境不稳定"，以区间范围呈现 |
| 第四步：生成瓶颈报告 | 热点根因无法在静态分析中确定 | 输出热点位置 + 耗时占比，标注"根因待确认" | 1 | 建议用户补充 profiler 火焰图 |
| 第五步：优化前后对比 | 无优化前基线 | 仅输出当前基准，标注"无基线对比" | — | 正常输出 |

## 关联子技能

- **代码审查** — 发现潜在性能问题后，用本技能定量验证
- **代码生成** — 生成代码后可用本技能跑基准测试验证性能
- **重构建议** — 重构前跑基线，重构后跑对比，量化重构收益
- **MySQL数据库** — SQL 性能问题跳转 `mysql-database` 做 EXPLAIN / 索引分析
- **测试用例生成** — benchmark 脚本应纳入测试套件持续跑基准
- **软件项目总控** — 软件项目上线前性能验收，提交基准数据作为交付物
- **网站项目总控** — 网站项目的性能指标、部署前压测和上线后监控基准
- **项目记忆管理** — 记录性能基线数据，作为后续回归对比依据
