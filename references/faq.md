# 常见问题答疑（FAQ）

本文件集中索引 dev-expert 技能使用中常见疑问、执行禁区、验证失败处置和边界外请求处理。详细规则出处以章节名标注，便于追溯到 SKILL.md 或对应 reference。

## 一、路由与子技能选择

**Q1：我说的话没命中任何关键词怎么办？**
A：优先用 `@<英文标识>` 显式指定（见 SKILL.md Step 1.2），或在输入中描述任务目标而非关键词（如"加个登录接口"会被路由到 `api-design`）。仍无法命中时，系统会按"无法唯一确定时向用户确认意图"规则向你索取意图。

**Q2：显式指定后，发现任务实际不该用这个子技能，会自动切换吗？**
A：不会自动切换。系统检测到强冲突时输出提示让你确认（见 SKILL.md Step 1.2 「任务-技能不匹配提示」表），你回复后才会切换；回复"按原指定执行"时立即按显式指定走，不再追问。

**Q3：多个子技能同时命中怎么决定？**
A：按 SKILL.md「子技能优先级矩阵」组合路由；无法组合时选匹配度最高的；无法唯一确定时向你确认。

**Q4：任务跨多个领域（如 CMS + 数据库 + 前端）怎么处理？**
A：按 SKILL.md「领域路由表」的协同 reference 顺序加载，先执行首选 reference，再按需加载协同 reference。一次任务最多加载 3 个 reference，超过则触发"过度路由"回退（见 SKILL.md「对话流异常处理边界」）。

## 二、执行禁区清单

以下做法在本技能中明确禁止，踩坑会导致交付无效或被安全闸门拦截：

| 禁区                                      | 原因                   | 正确做法                                    | 规则出处                              |
| ----------------------------------------- | ---------------------- | ------------------------------------------- | ------------------------------------- |
| 直拼 SQL 字符串                           | SQL 注入风险           | 用 PDO 预处理 / 参数绑定                    | `mysql-database`                      |
| Shell 写中文/UTF-8 文件                   | 编码损坏、中文乱码     | 用 Edit / Write 工具，或二进制读写          | SKILL.md 非 Git 文件操作安全协议      |
| 跨模块扩散修改                            | 破坏上下文延迟加载协议 | 一次只改当前目标文件 + 直接引用文件         | SKILL.md 上下文延迟加载协议           |
| 硬编码密钥/Token/密码                     | 安全闸门拦截           | 从环境变量读取，密钥不入代码                | SKILL.md 安全闸门 / `cms-development` |
| 跳过验证直接交付                          | 违反 Step 4 硬性前提   | 必须采集命令输出/测试报告/截图/API 响应之一 | SKILL.md Step 4 验证结果              |
| 安全/数据类失败重试                       | 失败重试基线 = 0       | 立即升级，不重试                            | SKILL.md 失败重试基线                 |
| 凭猜测补齐业务规则                        | 业务规则不明时禁止     | 高澄清级别，向用户索取输入                  | SKILL.md 澄清策略分级                 |
| 快速通道执行数据库写入                    | 退出快速通道条件       | 切换到"先方案后执行"模式                    | SKILL.md 快速通道机制                 |
| 跨模块(≥2)/批量替换(>10处) 在快速通道执行 | 误判快速通道           | 立即退出快速通道                            | SKILL.md 对话流异常处理边界           |

## 四、边界外请求

本技能不覆盖以下领域（详见 SKILL.md「本技能边界声明」章节）：用户调研、工时排期、容器深度编排、IDE 配置、缺陷跟踪流程、安全深度扫描。出现这些请求时只做边界说明，不声称已覆盖，不尝试用泛化方案替代专门流程。

## 五、显式调用与自动路由

**Q：显式调用会破坏自动识别吗？**
A：不会。显式调用是前置短路逻辑：仅当输入以 `@<合法英文标识>` 开头时跳过关键词路由，否则完全走原有路由表 + 优先级矩阵 + 意图三分法。拼写错误、邮箱、@提及等不触发显式调用，自动回退到关键词匹配。

**Q：显式调用后还能加载协同 reference 吗？**
A：可以。显式调用只跳过"路由匹配"环节，领域路由表的协同 reference 仍按需加载。例如 `@api-design` 仍会按需加载 `frontend-design`、`cms-development`。

**Q：显式调用后，意图三分法和安全闸门还生效吗？**
A：全部生效。显式调用只决定"用哪个子技能"，不决定"怎么执行"。意图三分法、安全闸门、澄清策略、验证闭环、复盘沉淀全部照常执行。

**Q：显式调用后任务-技能不匹配，提示几次？**
A：最多 1 次。用户确认后立即执行，不再追问；用户回复"按原指定执行"时按显式指定走。避免过度澄清（详见 SKILL.md「对话流异常处理边界 → 澄清过度」）。
